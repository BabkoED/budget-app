## Как устроен счёт

**Бюджет** — это период (с/по), список доходов и список плановых категорий.
Всё, что осталось после планов, делится на дни: это дневная норма.
Не потратил вчера — прибавилось сегодня, ушёл в минус — завтра меньше.

Дневная норма хранится **отрезками** (`budget.rates = [{from, v}]`), а не одним
числом. Поэтому правка дохода или плана в середине месяца меняет норму только
с сегодняшнего дня — прожитые дни пересчитываться задним числом не могут.
Это же делает пополнение категории «за счёт дневного бюджета»: в окне перевода
сразу видно, на сколько похудеет каждый оставшийся день.

Полоса под остатком на «Выписке» — это **остаток**, а не потраченное: с утра
полная, убывает по мере трат, как топливо в баке. При уходе в минус становится
красной на всю ширину (это флаг «вышел из бюджета», а не процент перерасхода —
пропорциональной шкалы для минуса нет).

## Синхронизация

Состояние — один jsonb на пользователя, но **записывается не целиком**:

- у каждой траты и каждого бюджета есть `mod` — момент последней правки;
- удаления оставляют метку в `state.rip` и живут полгода, потом вычищаются;
- при загрузке и перед каждой записью облако и локальная копия **сливаются**:
  по каждой сущности побеждает более свежая версия.

Без этого работа с двух устройств теряла данные: кто сохранился последним, тот
и затирал чужие траты. Плюс подписка на Supabase realtime и перечитывание при
возврате на вкладку — правки с телефона видны на ноутбуке сразу.

Локальный бэкап в `localStorage` пишется на каждое изменение и не зависит от
сети; при закрытии вкладки несохранённое дописывается через `fetch keepalive`.

## Обновление

```bash
cd ~/Documents/GitHub/budget-app
```

Заменить `index.html` на новую версию, затем:

```bash
git add . && git commit -m "описание правок" && git push origin main
```

GitHub Pages подхватит за 30–60 секунд. **PWA переустанавливать не нужно** —
service worker сам тянет свежую версию. При правках `index.html` имеет смысл
поднимать номер версии кэша в `sw.js`.

### Если push не проходит

```bash
unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY
```

Прокси V2RayU перехватывает git. Ошибка «fetch first» означает, что на GitHub
есть коммит, которого нет локально:

```bash
git pull origin main --no-rebase
```

## Инфраструктура

- **База:** Supabase, таблица `user_state` (jsonb на пользователя), RLS `auth.uid() = user_id`
- **Хостинг:** GitHub Pages (Netlify не работал с мобильного интернета в РФ)
- **DNS на reg.ru:** 4 A-записи `@` → `185.199.108.153` … `185.199.111.153`, CNAME `www` → `babkoed.github.io`, TXT `_github-pages-challenge-BabkoED` для верификации домена
- **Сброс пароля:** Supabase → Authentication → Users → Send password recovery

## Восстановление с нуля

1. Создать проект Supabase, выполнить `schema.sql` (включая блок realtime в конце)
2. Authentication → Providers → Email → выключить Confirm email
3. Подставить свои `SUPA_URL` и `SUPA_KEY` в `index.html`
4. Залить файлы в репозиторий, включить GitHub Pages (branch `main`, папка `/`)

## Производительность

Форматтеры `Intl` (числа, даты) создаются **один раз** и переиспользуются:
их конструктор в десятки раз дороже самого форматирования, а на списке в
сотню трат вызовов набегают сотни. Это давало основной лаг при рендере.

Расходы по бюджету считаются одним проходом (`getSpentMap`) и кэшируются:
по категориям, дневные, итог — плюс отдельно суммы «по сегодня», из которых
берут значения `calcDayBal` и `calcTotalBal`. Кэш привязан к дате, чтобы
приложение, оставленное открытым за полночь, не показывало вчерашние цифры.
Сбрасывается в `invalidateSpentCache()` из `save()` и загрузки облака.

## Чего пока нет

Общий бюджет на двоих. Сейчас данные привязаны к одному аккаунту: слияние
защищает от потери трат при работе с нескольких устройств под одним логином,
но отдельного входа для второго человека с общей базой и пометкой «кто внёс»
нет — это потребует своей таблицы участников и переписи RLS.
